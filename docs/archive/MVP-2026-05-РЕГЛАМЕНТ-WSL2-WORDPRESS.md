> 🗄 Архив: план MVP мая-2026 (WordPress/WSL2). Не реализован. Текущая архитектура — Astro + словари + SC. Принципы («ноль публичности», «цепочка доказательств», «аудит», «этика») перенесены в docs/02.

**Объект:** Братское захоронение «Корпечь» (с. Фронтовое, Ленинский р-н, Республика Крым)  
**Цель:** Подать уполномоченным гос. лицам структурированные, документально подтверждённые карточки для принятия решения: *«Внести имя в список для новых плит»* или *«Отклонить»*.  
**Принцип:** В публичное пространство не попадает ни одна непроверенная запись. Система работает только как внутренний конвейер подготовки.

## 🔄 Пошаговый регламент работы

### 🔹 Этап 1. Сбор и фильтрация (Оператор)
1. В WSL2 запускается сканер-контейнер.
2. Оператор вручную проходит авторизацию/капчу на портале (pamyat-naroda.ru / obd-memorial.ru).
3. Сканер в полуавтоматическом режиме извлекает карточки, где в поле захоронения/перезахоронения указано: `Корпечь`, `Фронтовое`, `выс. 66,3`, `Кой-Асан`.
4. Данные передаются в WordPress через локальный транспорт. Система создаёт записи со статусом `draft`.

### 🔹 Этап 2. Внутренняя обработка (Система)
1. WP автоматически:
   - Проверяет обязательные поля (ФИО, дата смерти, номер дела, источник).
   - Ищет дубли (по ФИО + дата + номер дела).
   - Помечает записи: `ready_for_template` или `needs_manual_check`.
2. Оператор видит список в админке, при необходимости добавляет заметки.

### 🔹 Этап 3. Формирование пакета для гос. органов (Оператор + Шаблоны)
1. В WP открывается раздел **«Шаблоны уведомлений»**.
2. Оператор визуально настраивает два блока (без правки кода):
   - **Email-шаблон** (для отправки уполномоченным)
   - **Веб-зеркало** (страница проверки по уникальной ссылке)
3. Система генерирует пакет: 1 письмо = 1 воин. Каждое письмо содержит уникальную ссылку-зеркало вида `/verify/ID_XXXX`.

### 🔹 Этап 4. Проверка и решение (Уполномоченные лица)
1. Гос. сотрудник получает письмо.
2. Переходит по ссылке-зеркалу → видит краткие данные + кнопку `Перейти к источнику ЦАМО`.
3. Сверяет документ, принимает решение в системе:
   - ✅ `Утвердить для плит`
   - ❌ `Отклонить` (с указанием причины)
   - 📝 `Запросить доп. проверку`
4. Решение фиксируется с датой, IP, логином. Статус записи обновляется.

### 🔹 Этап 5. Экспорт и передача (Оператор)
1. Фильтр: `status = approved_for_plate`.
2. Экспорт в `memorial_plates_final.csv` (формат для гравировальной мастерской).
3. Пакет передаётся по утверждённому каналу связи гос. учреждения.
4. Все остальные статусы остаются во внутреннем контуре. Публикация запрещена.

## 🎨 Как реализуется «визуальная подготовка шаблонов»

Вам не нужно писать PHP-шаблоны. В WordPress Studio создаётся простой конфигуратор:

### 1. Веб-зеркало (страница проверки)
- Создаётся файл `mu-plugins/verify-mirror-config.php`.
- В админке WP появляется меню: `Настройки → Шаблон веб-зеркала`.
- Поле: HTML-разметка с переменными:
  ```html
  <h2>{fio}</h2>
  <p>Звание: {rank} | Дата гибели: {death_date}</p>
  <p>Источник: <a href="{source_link}" target="_blank">Открыть документ ЦАМО</a></p>
  <form action="/verify/{id}" method="POST">
    <button name="action" value="approve">✅ Утвердить для плит</button>
    <button name="action" value="reject">❌ Отклонить</button>
  </form>
  ```
- Оператор меняет текст, цвета, расположение кнопок прямо в поле. Сохраняет → шаблон применяется мгновенно.

### 2. Email-уведомление
- Аналогичное поле в `Настройки → Шаблон письма`.
- Поддерживает переменные: `{fio}`, `{rank}`, `{unit}`, `{source_link}`, `{mirror_link}`, `{operator_name}`.
- Предпросмотр доступен по кнопке `Тестовый просмотр` (рендерит в модальном окне).

### 3. Хранение
- Шаблоны сохраняются в БД (опции WP) или в локальном JSON-файле `wp-content/config/templates.json`.
- Версионируются отдельно от кода сканера.

## 🔒 Правила безопасности и этики
1. **Ноль публичности.** Веб-зеркала не индексируются, доступны только по прямой ссылке. Нет поиска, нет каталога.
2. **Цепочка доказательств.** Каждое имя в итоговом CSV привязано к `tsamo_case_number` и `source_link`. Нет ссылки = нет в списке.
3. **Аудит.** Все действия логируются: кто запустил сканер, когда импортировано, кто утвердил, дата решения.
4. **Изоляция.** Сканер в WSL2/Docker. WP на Win11. Связь только локально. `auth-config.json` и токены вне репозитория.
5. **Этика.** Система не генерирует «возможно» или «предположительно». Только факт из документа + решение уполномоченного лица.
